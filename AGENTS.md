# AGENTS.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project: SpectrumAnalyzer

An AudioMuse-AI plugin for audio spectrum analysis that detects fake lossless files and transcodes via frequency-cutoff heuristics. Results include spectrograms (base64 PNG) and verdicts (CLEAN, CONSISTENT_LOSSY, LOWPASSED, TRANSCODED_LOSSY, FAKE_SUSPECT).

## Architecture

### Module design (three core modules + `integrity.py`)

- **`__init__.py`** — Flask blueprint for the web UI (album overview, per-track detail, settings). Handles database migration, plugin registration, and routes for scan/rescan/settings actions. Verdicts are color-coded; spectrograms are rendered inline.

- **`jobs.py`** — Background job logic. Three scan modes:
  - `changed`: skip tracks whose metadata fingerprint (path, size, bitrate, etc.) hasn't changed
  - `verify`: download every file, re-analyze only if audio MD5 differs (catches in-place edits invisible to metadata)
  - `force`: re-download and re-analyze everything
  - `scan_library_job()` is a parent orchestrator (must run on the **high** queue): it fans out one `scan_album_job()` per album onto the default queue with `parent_task_id`, throttles in-flight children to `config.MAX_QUEUED_ANALYSIS_JOBS`, and tracks done/remaining by polling the children's `task_status` rows (statuses + counters aggregated from their details JSON). In `changed` mode it settles all-unchanged albums itself without spawning a child. Tracks the registry cannot map to a catalogue id on their server are counted as `unmapped` (by the child for a launched album, by the parent for a settled one) and skipped; a registry failure fails that album, or skips it while planning, rather than keying rows by native ids. Cancellation: it checks its own row for REVOKED each poll; children check the parent's status at start. This mirrors core's `run_analysis_task`/`analyze_album_task` pattern.
  - `scan_album_job()` also runs standalone (no parent) for the album Re-analyze button.
  - `on_song_analyzed()` hook piggybacks on core analysis when the audio is already on disk (no extra download). It keys the row by the core's `_catalog_item_id` on the raw media item, falls back to the registry for the payload's `server_id` (else the active server), and skips the track when neither resolves.

- **`dsp.py`** — Audio DSP (librosa + numpy) and analysis pipeline:
  - **ffmpeg decode tier (0.4.0)**: librosa 1.0 (core 3.3.1+) removed the audioread backend, so `librosa.load` now reads only what libsndfile can open and every m4a/mp4/opus-in-mp4/wma/mpc file fails it. `_load_segment` and `_deep_spectrum` fall back to ffmpeg (`_ffmpeg_segment` / `_deep_spectrum`'s `read_chunk`, both reusing `_read_window_ffmpeg` + `_ffmpeg_sample_rate`) — deep-scanning an ALAC `.m4a` used to come back INCONCLUSIVE. The fallback is gated on `native_seekable is False` (`_probe_container` couldn't open it): for a container libsndfile CAN open, a librosa failure is the finding, and handing `truncated.flac` to ffmpeg would decode its intact prefix and launder a decode failure into a verdict. `_deep_spectrum` also only switches on a FIRST-chunk failure; a failure after audio decoded stays a mid-file `chunk_error`.
  - `_load_segment()` extracts one fixed-offset segment (offset 30s, falling back to 0s for short files) — **not** the middle of the track despite the old docstring; now only the last-resort fallback for `_load_windows()` (0.6.0, distributed segment sampling — see below).
  - **Distributed segment sampling (0.6.0)**: `_load_windows()` replaces the old single fixed-offset segment with several windows spread through the track, each scored independently, so one bad-luck sample can't miss a low-bandwidth passage elsewhere in the file. Two tiers, keyed off `_probe_container()`'s tier-2 result (`detected_fmt is not None` = SoundFile can open it): `_read_window_soundfile()` seek-and-read for FLAC/WAV/AIFF/MP3/OGG (`_NATIVE_WINDOW_POSITIONS`, 5 windows at ~10/30/50/70/85%, no subprocess cost) vs. `_read_window_ffmpeg()` (`-ss`/`-t` input-seeking to raw `f32le`, one ffmpeg spawn per window) for everything else — m4a/mp4/opus/wma/mpc — (`_FFMPEG_WINDOW_POSITIONS`, 3 windows at ~20/50/80%, the sample rate/duration for which comes from `_probe_ffprobe()`). `segment_seconds` keeps its existing meaning as the total decode budget, now `/= len(positions)` per window. Each window gets its own `_find_cutoff()`; windows within `_WINDOW_NEAR_SILENT_REF_DB = -85 dB` of true silence (not merely quiet content) are skipped via `_is_near_silent()`. The **minimum** cutoff among the surviving windows — not an average — becomes the primary window that drives `_edge_sharpness()`/`_shelf_level()`/`_verdict()`/the rendered spectrogram/`seg_offset`/`seg_seconds`, exactly as the old single window did; the other windows are reported alongside it in `details.windows.samples` (offset/seconds/cutoff_hz/silent) with `details.windows.agree` (spread ≤ `_WINDOW_AGREEMENT_TOLERANCE_HZ = 1500 Hz`, `null` when fewer than 2 valid windows) — since Phase 1b no longer just a UI-free signal: agreement corroborates a constant wall and disagreement can rescue a dark passage (see the Phase 1b bullet below), and the tolerance is now field-calibrated (walls/genuine spread 108–727 Hz, content-varying 2156–7617 Hz); `details.windows` itself is `null` in deep mode, where no windowing happens. `_load_windows()` falls back to the old single `_load_segment()` window when duration can't be determined, the file is too short to distribute, or every window in a tier fails to decode (e.g. no ffmpeg on PATH). Deep mode (`_deep_spectrum()`) already scans the whole file and is unaffected. `ANALYSIS_REV` bumped to 4.
  - `_spectrum()` computes STFT, reduces to per-frequency 95th-percentile profile (robust against silence/clicks).
  - `_find_cutoff()` (0.6.0, robust cutoff detection) locates the highest frequency within a drop threshold (default: 40 dB below 1–8 kHz reference) over a sustained band: at least 250 Hz wide with 75% of bins above threshold (gaps up to 120 Hz bridged first — real spectra have harmonic notches, an unbroken run is too strict), profile lightly smoothed (100 Hz) first. All these widths are in hertz, converted to bins from the file's actual bin resolution (`sr/N_FFT`) so behavior doesn't silently vary with sample rate. Isolated runs narrower than 80 Hz are excluded before gap-closing (so a lone pilot tone/spike can't get bridged into a real band and drag the cutoff up) and surfaced as the nullable `details.evidence.narrow_high_frequency_tone_present` flag when one sits ≥ 8 kHz. `ANALYSIS_REV` bumped to 2.
  - `_edge_sharpness()` measures rolloff steepness in dB/kHz (encoder low-pass filters are near-vertical; natural rolloff is gradual).
  - `_verdict()` decision logic: cutoff ≥ min(0.93 × Nyquist, 20.5 kHz) → CLEAN (genuine masters roll off at 20–21 kHz; near-Nyquist edges are meaningless), unless the container is hi-res (> 48 kHz sample rate) and the cutoff aligns with a standard lower rate's Nyquist (`_resample_match`, asymmetric −3%/+7% window: resampler leakage pushes detected cutoffs up) or sits below 23 kHz — then UPSAMPLED **only with corroboration** (silent shelf, aliasing images via `_best_alias_match` mirrored around candidate source Nyquists, or sharp edge); without corroboration it's a CLEAN "dark master?" note. Lossless + sharp edge + silent shelf (≤ −68 dB vs. reference — calibrated to real 16-bit re-encodes whose dither refills encoder silence at −73…−106; genuine noise sits ~−53) → FAKE_SUSPECT (this catches LAME 320→FLAC; cutoffs ≥ 20.5 kHz like AAC 256 still pass); sharp edge but audible noise above cutoff → LOWPASSED; gradual rolloff → LOWPASSED; lossy with low cutoff relative to declared bitrate → TRANSCODED_LOSSY **only for a codec in `_CALIBRATED_TRANSCODE_CODECS`** (currently `{'mp3'}` — the only codec `_expected_cutoff_for_bitrate`'s table is calibrated against; ffmpeg's native AAC/WMA legitimately cut lower than MP3 at the same declared bitrate, so uncalibrated codecs get a "no calibrated mapping" note instead of a verdict change); the MP3 gate itself never fully trusts the evidence either (`_TRANSCODE_GATE_CONFIDENCE_PENALTY = 0.10`, floored at 0.5, plus a note) since an intentionally low-passed first-generation MP3 is a legitimate alternative explanation — see `_resolve_lossy_codec()` for how the codec name reaches the gate (probed value, or suffix-trust for mp3 only, so the shipped 128-as-320 fixture keeps firing even without ffprobe); otherwise CONSISTENT_LOSSY. `ANALYSIS_REV` bumped to 3 (codec-aware transcode gating changes verdicts for non-MP3 lossy codecs and confidence for MP3).
  - **Segment-mode verdict wiring (Phase 1b)** — field-validated 2026-07-22 against five real 96 kHz tracks plus an independent forensic analysis (see IMPROVEMENT_PLAN.md "Phase 1b" for the case study); `ANALYSIS_REV` bumped to 6. Four changes, all on data segment mode already computes: (1) **program-level shelf reference** — the shelf is measured against the loudest valid window's 1–8 kHz median (`details.shelf_ref_db`), not the verdict window's own ref (`details.ref_level_db`), because the minimum-cutoff window is systematically a quiet passage whose own ref inflates the shelf by the ref deficit (a confirmed 96k upscale escaped the −68 dB gate by exactly this bias: −61.9 vs −77.5 dB); `SILENT_SHELF_DB = -68` itself unchanged. (2) **Window-consensus corroboration** — ≥3 valid windows agreeing (`windows.agree`) at a resample-matched cutoff add a "constant wall" note and +0.15 confidence (cap 0.9) to an UPSAMPLED verdict; deliberately **corroboration-only, never a trigger** — `dark_master_96k` (genuine) also pins a constant, resample-matched edge; what separates a wall from a dark master is the shelf. (3) **Variable-bandwidth guard** — hi-res lossless whose windows *disagree* while the widest reaches full bandwidth and the verdict window shows no machine signature (edge not sharp, shelf above `_DEEP_SILENCE_SHELF_DB = -85` — a genuinely dark passage reads "silent" vs the program ref (field: −71.7) but a resampler's floor sits at −103…−108) → CLEAN 'variable bandwidth (content-dependent)' 0.6 instead of a false LOWPASSED; sharp/deep-silent minima keep the suspect verdict (splice detector preserved). (4) **Envelope source-rate label** — `_consensus_source_rate()` names the wall from the agreeing windows' upper envelope (largest std Nyquist matched by any window, none past the leakage margin), fixing `fake_hires_48to96`'s "44.1 kHz" mislabel to 48 kHz; gated on agreement because disagreeing windows are contaminated by image leakage (ungated it would mislabel `fake_hires_44to96`). Plus LOWPASSED on a lossless container now words `est_source` as measured bandwidth ("content ends ~19.7 kHz"), not a lossy bitrate class that contradicts the verdict.
  - `_bit_depth_probe()` reads PCM via soundfile as int32 (left-justified) and computes effective bit depth from trailing zero bits: a >16-bit container with ≤16 effective bits is fake 24-bit → UPSCALED verdict (when spectrum is otherwise CLEAN) or a note. Stored as `container_bits`/`effective_bits` columns (meanings unchanged since 0.5.0).
  - **Bit-depth histogram (0.6.0)**: `_bit_depth_probe(path, full=deep)` builds a 33-bucket histogram of per-sample effective bit depth (`_bit_depth_window_stats`, shared by both modes and independently unit-testable) alongside the pre-existing exact minimum — the exact test itself (every tested nonzero sample padded) is unchanged and stays the *only* UPSCALED trigger. Segment mode reads the same ~30 s middle window as before (`details.bit_depth.coverage = 'sampled'`, confidence **0.9** when exact); deep mode instead chunks through the whole file bounded at `DEEP_MAX_SECONDS` like `_deep_spectrum()` (`coverage: 'full'`, confidence **0.95** when exact, or `'capped'` — still 0.95 — if the time budget was hit first). When the exact test fails but the histogram's mode is still ≤ 16 bits, a note reports `predominant_bit_depth` + `lower_bit_activity_fraction` (the fraction of samples with real content below 16 bits) as purely informational statistical evidence — dither, gain changes, SRC, or edits can all leave a few genuinely deeper samples without the file being any less of an upscale; this never changes the verdict. `details.bit_depth` gains these two fields plus `coverage` alongside the existing `container_bits`/`effective_bits`. `ANALYSIS_REV` bumped to 5 — the previously hardcoded 0.95 confidence for an exact UPSCALED hit is now 0.9 for a sampled-window confirmation and 0.95 only for a deep-mode full-file one, a real confidence correction on existing rows, not just a `details`-shape change.
  - **Codec probe (0.6.0), all 3 tiers**: `_sniff_dsd()` recognizes DSF/DFF by magic bytes (content, not extension) *before* any decode is attempted — the audioread/ffmpeg fallback would otherwise silently decode DSD noise shaping as full-bandwidth PCM and read it as CLEAN; a match short-circuits `analyze_file` straight to an `INCONCLUSIVE`/`unsupported` result via `_unsupported_format_result()`, `deep_eligible=False`. `_probe_container()` (tier 2) calls `soundfile.info()` to identify the actual container for formats libsndfile reads natively (FLAC/WAV/AIFF/MP3/OGG — verified libsndfile 1.2.2 reports these distinctly), also reading `.subtype` for the lossy formats (e.g. `MPEG_LAYER_III` → `mp3`) at no extra cost. `_probe_ffprobe()` (tier 3; renamed/extended from `_probe_codec_ffprobe` in 0.6.0) shells out to `ffprobe` once for codec **and** sample_rate **and** duration together — the codec lookup runs when a lossy suffix reaches `analyze_file` with no codec resolved yet (m4a/mp4/ogg-opus/wma/mpc — libsndfile can't open these), and the same call is reused (memoized) for the ffmpeg-tier windowing above when the container isn't SoundFile-seekable. This is what fixes ALAC-in-.m4a: an `m4a` suffix (always suffix-classified lossy otherwise) that ffprobe identifies as `alac` flips `is_lossless` to `True`. Any failure (missing binary, timeout, bad output) returns all-`None` — "unknown codec" — never a guess. Feeds an `is_lossless` override into `_verdict()` (default `None` = fall back to suffix-based `LOSSLESS_SUFFIXES`/`LOSSY_SUFFIXES` membership, unchanged). A probed/suffix disagreement sets `details.delivery.codec_mismatch`; the resolved codec itself (when any tier confirms one) is `details.delivery.codec`.
  - **Progressive integrity (0.6.0)**: every result's `details.integrity = {status, coverage, stream}` (`stream` since `ANALYSIS_REV` 8, see the container integrity bullet below). `status` ∈ `unsupported` (DSD)/`decode_failed`/`sampled_decode_ok`/`full_decode_ok`/`corrupt` (container check found damage; always `coverage: full`, always verdict `DAMAGED`); `coverage` ∈ `null`/`sampled`/`capped`/`partial`/`full`. Segment mode is always `sampled_decode_ok`+`sampled`. Deep mode: `_deep_spectrum()` reports `capped` (`total >= DEEP_MAX_SECONDS`, purely arithmetic) and `chunk_error` (the loop's `except Exception: break` fired — a real decode error, structurally distinct from the two natural-end-of-file break sites) — `full_decode_ok`+`full` only when neither fired; `chunk_error` → `sampled_decode_ok`+`partial`; `capped` → `sampled_decode_ok`+`capped`. Deliberately not attempted: distinguishing a genuine mid-file decode error from a backend that raises at true EOF instead of returning a short read — that's what the later "Minimum adversarial fixtures" item validates.
  - **Structured `details` namespacing (0.6.0)**: every fact in `details` has exactly one namespaced owner — decode state in `integrity.*`, codec mismatch/resolved codec in `delivery.*`, per-window data in `windows.*`, bit-depth columns in `bit_depth.*`, and the `evidence` namespace for flags with no dedicated section (`edge_machine_like`, `shelf_digitally_silent`, `alias_image_detected`, `narrow_high_frequency_tone_present`). New/future flags should extend the matching namespace rather than adding a flat top-level key. Evidence flags are nullable: `null` = not evaluated (e.g. `alias_image_detected` stays `null` outside `_verdict()`'s UPSAMPLED-candidate branch, where the alias-image correlation never runs), `false` = tested and absent — `_edge_sharpness()` returns `None` (not a misleading `0.0`) when there isn't enough band above the cutoff to measure, mirroring `_shelf_level()`'s existing `None`-for-unmeasurable contract, so `edge_machine_like` can distinguish "measured, not sharp" from "not measured" while the verdict-driving `sharp` boolean (`edge_db_khz is not None and edge_db_khz >= 25.0`) stays behaviorally unchanged. `details.analysis_rev` mirrors the top-level column for raw-dump auditability. Purely a `details`-shape change — no verdict/confidence value changed, `ANALYSIS_REV` not bumped for it.
  - `_deep_spectrum()` (deep=True on `analyze_file`, from the per-track Deep analyze button): chunked whole-file scan (120 s chunks, 30 min cap) producing a global max-hold profile, a 1-column/second spectrogram, and a per-second spectral-edge series. Measured calibration: encoder wall ±198 Hz, content-varying upsample ±1035 Hz, genuine dark master ±7236 Hz → edge variance ≥ 2000 Hz downgrades UPSAMPLED/FAKE_SUSPECT → LOWPASSED "likely genuine dark master"; ≤ 300 Hz (constant wall) raises confidence; a pinned edge (≥50% of seconds within 4% of a standard Nyquist, ≤5% above it) confirms a resampler wall regardless of variance. Quiet seconds (window ref < chunk ref − 25 dB) are skipped.
  - `verified` column (0.5.0): manual per-track flag toggled from the album page; excluded from all suspect counts/filters in `__init__.py` (`bad_expr`), preserved across re-analysis (not in the upsert column list).
  - `deep_pending` column (0.5.1, claim model in 0.4.0): the boolean "a deep scan is owed to this track" flag. Since 0.4.0 it is owned by a claim record: `deep_claim_id` (distinct uuid per claim), `deep_task_id` (the queued child), `deep_queue_backend` (`postgres` for every new claim; `rq` only on rows from the retired RQ queue, which the reconciler quarantines), `deep_claim_state` (`claimed`/`launched`/`running`/`failed`/`outcome_unknown`), `deep_claimed_at`, `deep_completed_claim_id`/`deep_completed_at` (claim-specific completion marker), and `deep_claim_detail` (compact JSON `{kind, message, recorded_at}`). `deep_pending` stays TRUE for every active/failed/unknown/legacy claim so the existing boolean deep controls keep disabling; retry eligibility is state-aware via `deep_claim_state`. Rows with `deep_pending` but null `deep_claim_id` are legacy (pre-0.4.0) and manual-retry-only. Shown as a state-aware badge on the song card and aggregated into per-album overview tags (deep scan ×N / verified ×N).
  - **Container integrity check (`ANALYSIS_REV` 8)**: `analyze_file` calls `integrity.check_file(path, deep)` once, right after the DSD guard, and stores the result as `details.integrity.stream` (`null` when nothing ran). `_integrity_state()` folds it in: a `damaged` stream overrides the decode-derived status with `corrupt`/`full` (coverage = how much of the file the status is based on, and both methods walk the whole file); a passing stream never upgrades `sampled_decode_ok` (progressive-integrity contract: a frame walk is not a decode). A damaged file becomes `DAMAGED` (its own primary verdict — a deliberate, maintainer-requested exception to the contract below; see there), `confidence` 1.0 (checksum/decoder evidence, not a heuristic), `deep_eligible=False`, `est_source` = `integrity.summarize()` (bad-frame count + merged regions), with the spectral reading kept as a note and all measurements/spectrogram kept. Rationale: zero-filled/truncated frames decode cleanly up to the damage, and decoded garbage is broadband noise that can launder a low-pass — so the spectral verdict of a damaged file is not evidence either way. `_inconclusive_result()` takes the stream too: a decode failure on a damaged FLAC comes back `DAMAGED` with the location; one with no provable damage (no FLAC marker, no ffmpeg check) stays `INCONCLUSIVE`/`decode_failed`.

  - `_render_spectrogram()` matplotlib-based PNG (spek-style color map, red line at detected cutoff), base64 encoded, tunable in settings, saved at `compress_level=6` (0.6.0, down from 9 — large CPU saving for a small size delta on an already time-pooled image). `analyze_file(..., skip_spectrogram_for_clean=False)` (0.6.0) skips the render call entirely for a CLEAN verdict when the `skip_clean_spectrograms` setting is on (default off); excluded from `analysis_rev` like `img_w`/`img_h` since it's a rendering choice, not verdict-relevant — toggling it doesn't force re-analysis and can't retroactively backfill spectrograms skipped while it was on (audio isn't retained after analysis).

- **`integrity.py`** — container-level damage detection, independent of the spectrum heuristics; every public function returns a dict and never raises. Picks the method by content (`is_flac_file`: `fLaC`, optionally behind an ID3v2 tag of any size), not suffix:
  - `check_flac(path, verify_md5)` — runs on **every scan** (no decode, no subprocess; ~0.05–0.3 s/track, ~150 ms average on the fixtures). `frame_index()` finds every 0xFFF8/0xFFF9 sync in numpy, parses headers that pass CRC-8 **and** agree with STREAMINFO (channels, bits, sample rate — deliberately *not* `max_blocksize`, which a buggy encoder can get wrong), and keeps the longest strictly increasing run of coded numbers (corruption drops/garbles headers but never reorders true ones; a false sync almost never fits). Spans between consecutive surviving headers are CRC-16-checked in one frame-parallel pass (`_crc16_spans`: end-aligned, two bytes per step via a 65536-entry table, ~12× a per-byte loop); a number gap counts the missing frames and still checks the span as the previous frame (a cleanly dropped frame doesn't blame its intact neighbour). The last frame has no next header, so `_frame_end()` walks its structure like a decoder (subframe headers, wasted bits, warm-up samples, LPC precision/coefficients, Rice/escape residual partitions, byte padding) to its one true end and the CRC-16 is checked *there*. **Never bound it by where a running CRC-16 happens to reach zero**: in an intact frame that also happens by chance (~1 per 64 KiB), and every corruption after such a point then verifies (PR #16 review, P1: 146/200 single-byte corruptions of a one-frame file passed). The walker is validated to land exactly on the next header on every frame of every fixture plus ffmpeg-encoded mono/6-ch/24/32-bit/level-0/level-12 streams; it costs a few ms for one frame and only runs on the last one, bounded by `max_frame_bytes()`. Bytes after the verified end are `trailing_bytes` — **not damage**, since libFLAC and ffmpeg both play appended junk to completion — unless they start with a frame sync (a final frame whose header failed CRC-8), which is damage. Then the frame sequence's end vs STREAMINFO `total_samples` catches a cut exactly on a frame boundary. Supports fixed and variable block size (variable: coded number = first sample). `verify_md5` (deep only) hashes the decoded stream in FLAC's MD5 layout ((bits+7)//8 little-endian bytes per sample) for **every depth FLAC allows (4–32 bit)**: libsndfile for 8/16/24 (no subprocess; the only path CI has), ffmpeg for the rest and as the fallback (its FLAC decoder left-justifies samples in s16/s32, so requesting exactly that PCM format and an arithmetic right shift give the true values). When neither can, `md5: not_checked` with `md5_detail` saying why — never silently (PR #16 review, P3). A mismatch with every frame intact is `damaged`; all-zero MD5 is `unset`, not damage. Tests use `tests/generate_adversarial_fixtures.py: verbatim_flac()` for depths no available encoder writes (12, 20…), cross-checked by libsndfile and ffmpeg decoding to the source samples. `zero_filled_bytes` counts ≥ 256-byte zero runs inside damaged spans (never legit inside a FLAC frame) — the transfer-gap fingerprint.
  - `check_ffmpeg(path)` — **deep scans only**, for every non-FLAC format (one subprocess + full decode per track is too much for a library scan, per the plan's cost rules). `ffmpeg -v error -err_detect crccheck+bitstream … -f null -progress pipe:1`: any error line = damaged; plus decoded length (`out_time_us`) vs the **audio stream's** declared duration (`-select_streams a:0 stream=duration`), tolerance max(1 s, 1 %). Never the container's `format.duration`: a container lasts as long as its longest stream, so an MP4 with 4 s of video and 1 s of audio would "decode short" (PR #16 review, P2). The container duration stands in only when the stream reports none and audio is the container's only stream (Matroska); otherwise no truncation is claimed. A declared duration ffprobe *estimated from the bitrate* (warning text) can't prove truncation → `truncated: null`. Zero false positives on every committed MP3/M4A/OGG fixture; catches `truncated.mp3` (22.4 s of a declared 45 s), which decodes without a single error. No ffmpeg → `not_checked`.
  - Region merging (< 1 s apart), `_MAX_REGIONS = 32` with `regions_capped`, and `summarize()` (the `est_source` line) live here too.

### Database

Results table with foreign key to core's `score(item_id)`, declared `ON UPDATE CASCADE ON DELETE CASCADE`. The UPDATE cascade is load-bearing: AudioMuse-AI 3.0 relabels `score.item_id` in place (native media-server ids → canonical `fp_...` ids) and only detaches its own FKs around that UPDATE — a plain FK blocks the whole core migration, the cascade migrates our rows losslessly. Fingerprints and MD5s stored to avoid redundant downloads/analysis.

**Analysis-revision stamp (0.4.0)**: `analysis_rev` column stores `dsp.analysis_rev(drop_db, segment_seconds)` (= hand-bumped `dsp.ANALYSIS_REV` folded with the verdict-relevant settings; rendering settings excluded). Every skip path requires a rev match in addition to its fingerprint/MD5 match — changed-mode fingerprint skip, verify/changed MD5 skip, the `on_song_analyzed` hook skip, and `scan_library_job`'s settle-without-child path. Bump `ANALYSIS_REV` whenever verdict logic changes; NULL rows (pre-0.4.0) re-analyze on the next non-force scan.

**Verdict/substatus contract (0.4.0, amended 0.5.0)**: `INCONCLUSIVE` is the primary verdict for files analysis couldn't meaningfully run on — decode failure, unsupported format (DSD). **Exception (0.5.0, maintainer decision): `DAMAGED`** is a second non-authenticity primary verdict for files the container check (`integrity.py`) proves broken (`integrity.status = corrupt`). Rationale: "replace this file" and "couldn't analyze this file" are different actions, and lumping damage under INCONCLUSIVE hid it among DSD/undecodable rows. It clears the plan's three objections to new primary verdicts: it can't vanish from the UI (`VERDICT_STYLE` badge + filter, plus a dedicated `n_damaged` overview count and a Damaged album column; albums sort by suspects, then damaged), it can't pollute suspect counts (`SUSPECT_VERDICTS` is an explicit tuple without it), and it can't be swept into bulk deep scans (`deep_eligible=False`; `_new_deep_claims` requires `deep_eligible`). Any further primary verdict needs the same three checks. INCONCLUSIVE was originally just decode failure (`dsp.analyze_file` catches `_load_segment`/`_deep_spectrum`'s `ValueError` and returns a normal-shaped result instead of raising, so decode failures flow through `_upsert` like any other verdict instead of vanishing silently from `scan_album_job`'s error counter or `on_song_analyzed`'s swallowed exception). Excluded from `SUSPECT_VERDICTS`/`bad_expr` but never invisible — the overview page carries dedicated `n_damaged` and `n_inconclusive` counts alongside suspect/lowpassed/verified, and it gets a filter checkbox for free via `VERDICT_STYLE`. Deep-scan eligibility is a separate `deep_eligible` column (`BOOLEAN NOT NULL DEFAULT TRUE`), not derived from the primary verdict — decode failure sets it `False` (retrying won't help); both deep-scan gates (`deep_rescan` route, `_queue_deep_non_clean`) and the per-track "Deep analyze" button check it. Unsupported-codec and DSD-without-ffmpeg substatuses are deliberately deferred to the container/codec-probe item, which is what will actually detect them.

**ID model (0.3.0)**: `item_id` = the canonical id `score` is keyed by (AudioMuse-AI 3.x); `provider_track_id`/`server_id` columns keep the native id for `download_track`/rescans.

**Task-row ids (0.3.0, Postgres queue since 0.4.0)**: task_status rows for top-level jobs MUST be keyed by the id the CORE queued the job under, which `jobs._current_task_id()` reads from `taskqueue.current_task_id()`. The queue row already exists when the task starts, so a self-invented id would mean a duplicate row in Active Tasks beside it, a Cancel that tombstones the row nobody is polling, and a `func IS NULL` row exposed to the stale-in-process sweep. Routes never pre-create rows: the core's finish merges the task's return value into the details already on the row, and a terminal row the task wrote itself through `save_task_status` is left as written.

**Task-id contract (0.4.0)**: `scan_library_job`, `bulk_analyze_job` and a root `scan_album_job` (no parent) take `task_id or _current_task_id()` through `jobs._job_task_id`, and raise `RuntimeError` when there is neither: they never invent a uuid. A parent-launched `scan_album_job` keeps the explicit bookkeeping id its parent passed. Parent-launched children keep uuid ids: the parent reads their counters from task_status rows linked by `parent_task_id`, and the queue's own row is a root with no such link (see Queue admission). They are reconciled by `_child_job_lost`, which polls the queue row (`_queue_job_over`: terminal, or deleted by retention, both meaning the job ended). Because those uuid rows are written once at launch, `_touch_live_children` refreshes any that approach `QUEUE_INLINE_STALE_SECONDS` (30 min) so a child queued behind a long backlog isn't failed out from under the parent.

**Bulk fan-out (0.4.0)**: `jobs.bulk_analyze_job` is the parent for EVERY bulk track action (deep-scan-all, force-requeue, bulk selected, album re-analyze track-by-track). A route cannot loop over `enqueue()`: the guard below counts live `plugin.%` roots and the first track a route queues is one, so the second enqueue is refused. The orchestrator runs on the high queue and fans out from inside a worker (guard-exempt), through `_launch_throttled`, which caps in-flight children at `MAX_QUEUED_ANALYSIS_JOBS` and then drains — the same shape `scan_library_job` uses for albums, one level down. Children are plain `analyze_track_job` enqueues with no task row of their own, so the parent tracks them by the handle `enqueue()` returned: `_prune_finished` batches one `_queue_states` query over the task ids (absent row = swept by retention = finished). Claiming moved INTO the job via `_new_deep_claims`/`_requeue_claims`: a route cannot know whether the job it queues will ever run, so each claimed track gets a distinct claim id (`deep_claim_id`) that the child carries and every deep-state write is fenced on. A launch failure (`_LaunchFailed`) cleans only never-enqueued normal claims (clear) and restores the prior record for never-enqueued `requeue_all` claims (compare-and-set on the fresh claim id), then re-raises the original cause so the parent row stays FAILURE. Cancelling the parent clears what it claimed but never launched; already-launched children keep going (they are queue-level roots — see the guard note below), though the core's global cancel stops everything.

**Queue admission (0.4.0)**: `plugin.api.enqueue()` refuses a plugin enqueue made from the WEB process while any queue job is live (a core analysis, a cleaning run, another plugin's task, or one of our own scans) and raises; a job already running on a worker is exempt, which is what lets `scan_library_job` fan its children out. Every route therefore queues through `__init__._enqueue`, which turns the refusal into `_QueueRefused` and a 409 page instead of a 500. The claim-then-enqueue routes clear their own fresh claim on refusal or a generic enqueue exception (only the matching new claim id) because the claim is what makes those buttons idempotent. Bulk actions do not enqueue per track at all any more (see Bulk fan-out above), so the only routes that still enqueue directly are the single-track buttons and the two scan starts. Note that `plugin.api.enqueue` never forwards `parent_task_id` to the queue, so our album children are queue-level ROOTS — the core's cancel-cascade cannot reach them and only our own cooperative parent-status check stops them.

**Multi-server (0.3.0)**: the core's server binding (`plugin.api.use_server`) is a contextvar that does NOT cross job boundaries, so every job binds its own server via `jobs._bind_server` (nullcontext when the server is None, i.e. the default). UI scans pass `all_servers=True` → `scan_library_job` plans `(server_id, album)` pairs over `_list_server_ids()` and launches each `scan_album_job` with its `server_id`; standalone album re-analyze recovers it from stored rows (`_album_server`); `_analyze_track` binds `row_server` so re-downloads hit the right catalogue. Cron entry (`scan_changed_task`) stays single-run — a schedule's server scope makes the core run it once per server, already bound (`_active_server_id()` short-circuits the fan-out). Tracks shared between servers collapse onto one canonical id (no duplicate rows); their per-server path/size metadata can flip the fingerprint between alternating scans, costing a re-download that ends `unchanged` via the MD5 check. Translation happens at the edges via `jobs._native_to_fp`/`_fp_to_native` (wrapping `tasks.mediaserver.registry.reverse_translate_ids`/`translate_ids`; a registry failure raises rather than falling back to native ids, and an id the registry leaves out is `unmapped`). One batched translation per album, mirroring core's `attach_catalog_item_ids`. The v3 `on_song_analyzed` payload's `item_id` is the NATIVE id — the canonical id is `media_item['_catalog_item_id']`. `migrate()._migrate_v3_ids` = columns → defensive re-key via `track_server_map` → FK repair (NOT VALID + best-effort VALIDATE) → provider backfill; all idempotent, tested against live Postgres in `scratchpad` (four upgrade scenarios).

### Plugin integration points

- Settings page for segment length, cutoff threshold, spectrogram dimensions, optional on_song_analyzed hook toggle, and optional skip-spectrogram-for-CLEAN toggle.
- Optional cron task (`plugin.spectrum_analyzer.scan_changed`, seeded disabled, Sunday 04:00).
- Optional cron task (`plugin.spectrum_analyzer.recover_deep_pending`, seeded disabled, every 3 h) — a bounded reconciler, not a retryer: it reads each owned deep claim's real queue state (Postgres `task_status`) and only settles the plugin's own claim markers — clears a confirmed terminal outcome, records `failed` on a confirmed failure, and marks `outcome_unknown` when the queue row is gone. Live and unreadable claims are left untouched. Claims with `deep_queue_backend = 'rq'` are quarantined as `outcome_unknown` whatever their queue row or completion marker says, since RQ is no longer read (`_quarantine_legacy_backend`). A quarantined claimless row is excluded from `requeue_all` and survives a plain re-analysis, so only the confirmed `requeue_unknown` select reaches it. It never re-queues: an uncertain outcome is a durable badge plus an explicit user-authorized retry, because the core already persists queued work and reclaims work whose worker died.
- Manual re-analyze button per track (enqueued to the `high` queue).

## Development workflow

- **Run tests**: `python3 -m unittest discover tests -v` from the repo root (needs `numpy soundfile matplotlib` via pip; librosa is stubbed by `tests/librosa_stub.py`). `tests/fixtures/` holds committed 45 s ground-truth files (genuine masters + every fake type built from a confirmed-genuine DSD source). Always run after touching `dsp.py`.
- **Ad-hoc analysis**: `python3 tests/run_verdicts.py "path::suffix::kbps::EXPECTED::seg|deep"`.
- **Integrity tests**: `tests/test_integrity.py` builds its damage variants (zero-fill burst, bit flip, dropped frame, cut on a frame boundary, MD5 flip/zero, ID3v2/ID3v1/junk, variable-block-size rewrite, zero-filled MP3) on the fly from committed fixtures via the transforms in `tests/generate_adversarial_fixtures.py` — they are not committed (`--integrity DIR` writes them out). ffmpeg-dependent tests are gated both ways like the existing codec tests; always also run the suite with ffmpeg hidden from PATH (CI has none). Any change to `integrity.py` must keep every committed fixture at `result: ok` / `md5: match` (no false alarms).
- **Build**: `./build.sh [version|local]` — `local` replaces `dist-local/spectrum_analyzer.zip` for the fast dev loop (`dist-local/` carries its own fixed manifest.json/plugin.json catalog, always pointing at that unversioned zip; never touched by the script). A version (or no argument = newest zip in `dist/`, falling back to `plugin.json`) builds `dist/spectrum_analyzer-<version>.zip` and rewrites the matching `plugin.json` entry's `sourceUrl`, warning if the version has no entry yet. Old versioned zips are kept so published entries stay downloadable.
- **Release** (CI/CD, `.github/workflows/build.yml`): releases happen only when a **PR is merged into main**. The PR must change the code *and* add a new top entry (version + changelog) to `plugins/SpectrumAnalyzer/plugin.json` (full history in `CHANGELOG.md`). Tests run on every PR update and again on the merge. Before building, CI **fails** if (a) any published zip is missing or its md5 no longer matches its plugin.json checksum, or (b) plugin code changed but the newest version is already built (no bump). Otherwise it builds `dist/spectrum_analyzer-<version>.zip` and commits it plus the entry's `sourceUrl`/md5 `checksum` back (`[skip ci]`). Direct pushes to main do not release — protect main so everything lands via PRs. **Published versions are immutable** (installed copies re-verify by checksum, e.g. after a plugins-volume wipe); build.sh enforces this locally too (`FORCE=1` only for never-published versions). Per core docs: blueprint name must equal the plugin id, the zip must not contain plugin.json, `on_install` must be re-runnable, `requirements` carries pip version pins. Community-catalog listing = a one-entry PR to NeptuneHub/AudioMuse-AI-plugins' `manifest.json` pointing `pluginUrl` at this repo's raw `plugins/SpectrumAnalyzer/plugin.json` (the externally-hosted model used by the Lumae plugins) — this repo stays the single source of truth for code, releases and checksums.
- **Regenerate fixtures**: `./tests/generate_fixtures.sh <genuine-hires-file> tests/fixtures [ffmpeg] [start] [dur]` (committed set: start=60, dur=45). Calibration constants measured from these fixtures are documented in `tests/README.md` — update both when retuning thresholds. The Phase-1 minimum-adversarial-fixtures set (`tests/generate_adversarial_fixtures.py`) is separate — built straight from the already-committed `genuine_cd_1644.flac` (and, for the Phase-1b `variable_bandwidth_96k.flac`, `genuine_dsd_2496.flac`), no external source needed; only its MP3/AAC/ALAC/Opus/Vorbis fixtures need a real ffmpeg (skipped with a printed note when absent, so the script is always safe to run). The Phase-1b pair (`upsampled_quiet_intro_44to96.flac`, `variable_bandwidth_96k.flac`) is pure numpy/soundfile with seeded RNG and hand-calibrated noise floors — see the comments in their generator functions and tests/README.md before retuning.
- The web/jobs layers (`__init__.py`, `jobs.py`) still require a live AudioMuse instance to test, with one exception: `tests/test_bulk_jobs.py` stubs `plugin.api`, the media-server registry and a minimal task_status/results table so the bulk fan-out ORCHESTRATION (`bulk_analyze_job`, `_launch_throttled`, `_prune_finished`, the claim and the cancel path) runs as real code. Its `FakeCursor` matches on statement fragments, so editing those statements means editing that file too.
- `tests/test_postgres_integration.py` runs the real `migrate()` and the claim / quarantine / reconciler SQL against a throwaway Postgres (needs `psycopg2`; skipped unless `SA_TEST_PG_DSN` is set, and it DROPS the public schema of that database). The core tables are hand-copied from core v3.6.4 and `plugin.api` is still a stub, so it checks the plugin's SQL, not the core's behavior. Run it after touching any SQL in `__init__.py` or `jobs.py`; the command is in the file's docstring.
- **Dependencies**: librosa, numpy (included in AudioMuse-AI), matplotlib (declared in `plugin.json`, auto-installed). Core 3.3.1 moved to numpy 2.4.6 and librosa 1.0, so the matplotlib floor is `>=3.10`: matplotlib 3.8's C extensions are built against the numpy 1.x ABI and fail to import under numpy 2, and pip does not upgrade an already-satisfied requirement, so an install that once resolved 3.8.x would keep it and lose every spectrogram. `dsp.py` itself is numpy-2 clean (no removed aliases, no `copy=False`, `np.ptp` is the function form).
- **Change detection strategy** is a two-layer optimization: (1) metadata fingerprint for cheap skips, (2) audio MD5 to catch byte-level changes. This avoids downloading unchanged files during incremental scans.
- **Spectrogram caching**: base64-encoded PNG stored in Postgres. Database size ~100–300 KB per spectrogram (default 800×280 px); 10k songs ≈ 1–3 GB.
